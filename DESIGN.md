# Design

## Purpose

actor-subagents adds a bounded actor swarm to one foreground pi session. Named background agents have independent model sessions, communicate through explicit messages, and form an ownership tree rooted at `main`. The foreground is the main human conversation; child transcripts remain visible in history and the panel, whose input can send a real user turn to a child. The foreground branch is readable by every agent through `subagent_history` so a child can find the context its task came from; the child extension policy does not restrict this.

## Runtime structure

`index.ts` is the imperative shell around the in-memory `Engine`. It registers pi tools and commands, translates pi lifecycle events into engine state, creates child sessions through the SDK, persists membership, and renders the roster. Pure modules hold routing, ordering, status, formatting, model-resolution, and restoration rules so those rules can be tested without pi or the TUI.

Each child session is created with:

- the main process's model registry, credentials, and global agent instructions;
- its own system prompt and session file;
- orchestration tools supplied directly as pi `customTools`;
- recursive extension discovery disabled;
- the tool-result timestamp hook, registered in process as an inline extension factory;
- the extension paths granted by the `childExtensions` policy in `settings.json`; and
- unattended extension bindings with captured footer statuses (`bind-headless-extensions.ts`): mode `print`, `hasUI` false.

No human watches a child, but its extensions' footer statuses (`ctx.ui.setStatus`) belong in the roster. Pi has one switch for both: any capturing UI context makes `ctx.hasUI` true, and extensions read `hasUI` as "a human can answer dialogs". Under `hasUI` true, an extension that asks before acting would get an instant cancellation, which reaches the model as "the user declined" although nobody was asked. A child therefore captures `setStatus` but reports `ctx.hasUI === false` (an override on its own runner instance) and `ctx.mode === "print"`, so extensions take their documented headless paths; every other UI method keeps Pi's no-op behavior. The cost: only statuses set unconditionally (the Pi idiom, a no-op without a UI) are captured, not those an extension sets only when `hasUI` is true. A Pi capability that separates "has a display" from "can answer dialogs" would remove the override. The statuses are sanitized to plain text at that boundary (`extension-status.ts`) and, if `childExtensionStatusKeys` is set in `settings.json`, filtered to those keys there (display-only, so an invalid value shows every key). They are owned by the child session, so a late write from a killed child cannot reach a re-spawned namesake. They are not persisted: extensions publish them again on `session_start`. Three status sources stay separate by provenance: the system status is derived by the host, `set_status` is reported by the agent, extension statuses by its extensions. The agent's own status describes the state it rested in, so `spawner.ts` clears it (with its ETA) at the first accepted turn after the agent ended a turn: a final assistant message without tool calls, or a settled run. A failed attempt that Pi retries is not an end of turn, and a paused agent's refused turn keeps the status. The roster joins extension statuses into one column right after the system status, as Pi's footer joins them; `list_subagents` shows them with their keys.

A pi hook only fires in the session that registered it, so the timestamp that lets an agent perceive elapsed time has to be installed into every child separately. It travels the same in-process route as the orchestration tools rather than as a file path, which keeps the granted-paths list an exact picture of the foreign-capability policy. The policy is read on every spawn. Parsing is fail-closed: missing, unreadable, malformed, or structurally invalid input becomes an empty list. actor-subagents itself is not loaded recursively in children because its tools are already injected.

## Actor model

The engine owns agent records, spawn parentage, directed mailboxes, activity, status, and lifecycle transitions. Spawning reserves a unique name and enforces the agent-count and depth caps before asynchronous child creation. The caps come from the same `settings.json` and are fixed for the engine's lifetime, because a swarm's limits cannot meaningfully change under the agents already running against them; unlike the capability policy they default per field rather than failing closed. Who spawns, owns: an agent may pause, resume and kill only its strict descendants, and retune itself or its descendants; `main` is the root and owns every agent. The human's commands and panel act as the actor `user`, and session restore as `restore`; both carry `main`'s authority but stay distinct as provenance, so the swarm can tell the human's actions from `main`'s. The acting agent is bound into each agent's toolset, never taken from tool arguments. Messaging and inspection are unrestricted. Killing an agent cascades through its descendants.

Pause is one flag per agent, holding the actor that set it, and the paused state is derived: an agent is paused while it or any ancestor carries the flag, so pausing an agent holds its whole subtree, including agents spawned into it later. Pausing requests aborts for running turns in the held subtree; the request can return before abort completion and cannot undo side effects. Pause and resume take effect in call order; an agent whose abort is still landing counts as stopped, so its mail buffers and no turn starts, and a resume releases the mailbox and re-triggers the interrupted work only once that abort is done and the agent is still not paused; delivery to a paused agent buffers without losing ordering. Any turn refused because the agent is stopped (paused, or its abort still landing), such as an extension message sent with `triggerTurn` or a hand-off that raced a pause, counts as interrupted work, so resume re-triggers it instead of leaving that message unread. The engine starts every abort itself (pause or refused turn) and tracks it until it lands, so a resume never steers its nudge into a dying run. Aborts are tracked per agent record, not name, and a kill detaches every session of the subtree before it awaits any teardown, so neither a late abort nor a late event of a killed agent reaches a re-spawned namesake. Resuming clears only the named agents' own flags; agents thereby released have their mailboxes delivered as one ordered batch and may receive a resume nudge for interrupted work, while a pause set by a lower owner stays in place. For pause and resume tools, omitted, empty or whitespace-only name lists select the caller's direct children; kill requires an explicit non-empty list. A restored session comes up with `main`'s direct children paused; `main` adopts any restored agent whose parent was not restored, so that holds the whole restored swarm. The SDK is asked to abort the agent's running work; the extension does not guarantee that all tool effects have ceased when the pause result returns.

The persistent roster (`roster-widget.ts`) opens the shared panel lifecycle in `index.ts` on a row click, selecting that agent. `/subagents` uses the same lifecycle without a requested selection. The panel (`panel.ts`) selects by agent identity so traffic-driven row reordering cannot change the target. Row clicks resolve against the last rendered frame. Pi 1.2.0's native component-local mouse events handle clicks, drag detection and wheel deltas in fullscreen mode; the extension does not parse terminal mouse sequences. The top-right `Esc` label and Escape key close the panel and restore the persistent roster. Keyboard navigation remains available without fullscreen mode.

The panel's input box is the human speaking directly to the selected agent: it arrives as a real user turn, and is refused rather than buffered when the agent is paused or still spawning.

Sending reports routing (handed off, buffered or failed) and observed receiver activity, not an acknowledgement that the message was read or acted on. Child delivery stays fire-and-forget. The brief activity watch uses engine events and current state; an already active receiver does not establish a reaction to this message, and no activity observed during the window does not mean the receiver ignored it. Foreground activity is not watched. A busy child receives steering at a model boundary; paused agents and agents with an abort still pending buffer messages.

Ordinary assistant output is visible through history and the panel but is not pushed to peers. `send_message` is the explicit routing channel. Retuning changes the next model request, possibly within the current logical run, without changing an in-flight request.

When a pause, resume or kill names or flags an agent, or an agent enters the error state (once per failed run, whether the turn threw or the model gave up after retries), the engine attempts a lifecycle notice to its eligible direct parent: what happened, to which children, by whom, the local time, and for an error the reason — facts, no advice. An operation groups its notices by eligible parent. A resume notice distinguishes agents released from those whose own pause was cleared but who remain held by an ancestor; the latter names that holder rather than claiming they resumed. Nobody is told about their own action, nor after the parent is gone; a kill decides that after the whole operation, so a parent taken down with its child is skipped. The subtree that follows a named agent is not reported separately: its own parents are being acted on too.

Pause, resume and kill notices are silent transcript appends, not turn requests. Append failures are caught without a reported failure or retry, so a notice is not guaranteed to arrive; an appended notice is available as context for the parent's next turn. An append while the agent's run is active would land inside that run, possibly between a tool call and its result, so the engine queues these notices while the agent is busy and appends them after its run or hand-off settles. Pause does not bypass that busy check, and these silent notices never enter the paused mailbox.

Errors instead use ordinary routed scheduler messages to the live direct parent, including `main`: request a turn when idle, steer after current tools before the next model request when busy, or buffer while paused or still stopping. This is one message, not an active delivery plus a silent copy. A new error-state transition qualifies, including operational delivery or abort failures reported by the engine. Repeated reports within the same error state are suppressed; completed logical runs are assessed after retries settle. Retry attempts, handled tool errors, deliberate aborts and truncated output do not independently wake a parent. No child is restarted automatically, no absent parent is replaced by an arbitrary ancestor, and restore does not emit synthetic errors. A parent delivery failure follows the normal error path if that parent itself enters error. Delivery is not an acknowledgement that the parent read or handled the child's error.

A status has two renderings (`agent-status.ts`). Tables and columns — the TUI roster, the panel roster, `list_subagents` — show the short label: `spawning`, `paused`, `thinking`, `writing`, the tool name (or `tool` when unknown), `idle`, `error`, `truncated`. Where a single agent is read on purpose — the `subagent_history` header, `send_message`/`spawn_subagent` delivery results, the panel's line for the selected agent — a pause adds its cause: `paused by user`, `paused (held by lead, paused by user)`. An error's reason is in neither: it can be a provider's long raw message, so it is read in the parent's error notice, the `subagent_history` header line `last run error: <reason>`, and the panel's selected-agent line. History retains that last-run context while paused; the panel shows the pause cause instead, and shows an error reason only when currently errored. History is a clipped text projection, omitting nontext content; its `spawn prompt` section is the supplied spawn prompt, not the full effective system prompt. Resume nudges name the actor, and tool results count requested nudges rather than confirmed starts.

Messages use one structured custom pi message type; lifecycle messages use it too, with the engine's own sender `scheduler`. A routed scheduler error part carries `actionable: true`; parsing and batching preserve that flag. Restore skips only entirely passive scheduler batches, including unmarked legacy notices, so persisted unhandled errors remain interrupted input for explicit resume rather than synthetic error replay. The structure preserves sender and recipient provenance for routing, model context, and TUI rendering. A live foreground sink on `globalThis` prevents a reloaded extension instance from delivering through a stale pi handle.

## Persistence and reload compatibility

For a file-backed main session, state lives at:

```text
<main-session-dir>/subagents/<main-session-id>/
  roster.json
  <agent-name>.jsonl
```

`roster.json` records enough validated membership and session metadata to rebuild the swarm. Child conversations remain native pi JSONL sessions. Reopening the same file-backed main session after a process restart attempts to restore saved agents paused; a new or in-memory main session does not restore them. Missing session files, unavailable models and reopen failures can skip agents. Roster write failures are caught without being reported, so membership persistence is not guaranteed. Buffered messages, queued lifecycle notices, custom status and ETA are in-memory and do not survive restart. The `spawn_subagent` description states these limits. Malformed roster entries are ignored rather than trusted.

### Interrupted work

An assistant tool call and its result are separate persisted messages. An interruption can therefore leave a call without a result even when the tool's side effect already happened. A missing result means an unknown outcome, not proof of non-execution.

Restore reconnects the observed transcript without appending synthetic tool results. Restored agents remain paused through their ancestry; explicit resume supplies an interrupted agent with a nudge to inspect actual state before retrying side effects. The extension does not replay tools. Exactly-once execution and rollback would require support from the tools or target systems, not transcript repair. Existing synthetic results from earlier versions are not migrated.

Pi owns outbound provider-message normalization (Separation of Concerns): its direct built-in adapters normalize incomplete tool-call/result sequences at the request boundary without changing the stored transcript. Resume depends on that SDK/provider contract. Regression tests exercise the installed, development-pinned Pi version; they do not certify arbitrary future versions, the `pi-messages` gateway, or custom-provider paths. Those paths must provide equivalent normalization to support interrupted histories safely.

### Process reload

The engine, foreground sink, foreground state, and restore guard use versioned `__subagents*` keys on `globalThis`. Those key names are runtime compatibility contracts: they keep same-version `/reload` connected to live children and deliberately change only when an incompatible in-memory shape requires a new singleton. A reload that finds an engine of an earlier generation shuts its children down before building the new one, because that generation's records are unreachable from the new code while its sessions would keep running; the roster on disk is what carries the swarm to the next start.

## Interfaces

The agent-facing tools, shared by every agent (`set_status` by background agents only), are `spawn_subagent`, `send_message`, `set_subagent_model`, `list_subagents`, `subagent_history`, `set_status`, `pause_subagents`, `resume_subagents`, and `kill_subagents`. A control tool's name is plural exactly when it takes a `names` list; pause, resume and kill report a per-target outcome plus the agents actually affected. Foreground commands are `/subagents`, `/subagents-pause`, `/subagents-resume`, and `/subagents-kill`. Their names, result/message formats, roster format, domain vocabulary, and persistence layout are compatibility surfaces.

The package has no service or network interface of its own. Model traffic and credentials are handled by pi. The extension inherits pi's process authority, so the explicit `childExtensions` policy in `<pi agent dir>/actor-subagents/settings.json` is the primary capability boundary introduced here.
